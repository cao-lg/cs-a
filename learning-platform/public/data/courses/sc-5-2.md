仓储不是新词。它从『账物相符』这种土办法，一路进化到今天的算法调度。先凭直觉答：它经过了哪几次跃迁，核心转变是什么？

:::reveal{title="看解析：仓储的三次范式跃迁与三转变"}
:::steps{
  title="仓储的三次范式跃迁"
  theme="coral"
  steps=[
    {title:"早期（50–80年代）", desc:"以『账物相符』为目标，纸质台账 + 人工盘点，信息滞后、差错率高。"},
    {title:"信息化（90年代–2010）", desc:"ERP、WMS 上线，库存电子化。但多是『线下流程的线上复制』，数据孤岛严重，决策仍靠经验。"},

  ]
}

:::question{title="第二问：传统仓储的四个『系统性』痛点", hint="先想：老张通宵，是他勤快，还是系统让他不得不勤快？"}
别急着上系统。先看看旧仓库到底卡在哪——先凭直觉列出：传统仓储有哪些系统性痛点？

:::reveal{title="看解析：传统仓储的四个系统性痛点"}
| 痛点 | 表现 | 代价 |
| --- | --- | --- |
| **信息孤岛 / 数据滞后** | ERP 凌晨才同步一次库存，电商订单实时涌入 | "超卖"与"缺货"并存；10万 SKU 仓可能 5000–8000 个账实不符 |
| **人效瓶颈** | "人找货"模式，拣货员 60%+ 时间花在走路找货 | 日均 3 万步，有效拣货不足 3 小时；新员工数周才熟库位 |
| **结构性失衡** | 缺数据驱动，该多的不多、该少的不少 | 畅销品断货、滞销品积压，季末被迫清仓 |
| **被动滞后** | 异常事后才发现 | 冷库温度故障未察觉，200 万医药冷链变质；大促拥堵次日晨会才知 |

> 💭 **小北**："原来『老张通宵』不是他勤快，是系统让他不得不勤快——信息迟、人效低、异常看不见，只能拿人命填坑。"
